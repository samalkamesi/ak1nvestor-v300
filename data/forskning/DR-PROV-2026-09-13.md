natt-dumpar är `public.system_events` en tom tabell (COPY-block med 0 rader)

databasobjekt (trolig vy) vars 154 164 rader INTE finns i natt-dumpen under
något namn (ingen tabell i dumpen har dem; de 8 vyerna i dumpen heter annat).

Konsekvens: **händelseloggen kan endast återställas från moln-backupen**
(via REST-inläsning enligt DRIFTSBOKEN kap 4c) — vilket är just den kedja som
IDAG är bevisad komplett (154 164 rader giltiga). Åtgärdsförslag (till
sudofönstret, appendix A steg 5): identifiera det riktiga objektet och
komplettera natt-jobbet så även event-datat kommer med i SQL-dumpen — eller
fastslå moln-backupen som permanent huvudväg för händelseloggen (den körs
redan varje timme av hybrid-sync när datorn är på, plus vid behov som idag).
Båda kedjorna tillsammans = komplett DR; enbart natt-dumpen = ej komplett.

## 8. Slutsats — RTO (återhämtningstid)

- **Dataskiktet (SQL-kedjan):** senast BEVISADE fulla återställningstid är
  **20 sekunder** (våg 98 F3, 2026-09-11) för 29,4 MB dump → 60 tabeller →
  1 187 291 rader. Dagens dump är jämförbar (28,5 MB) och integritetsbevisad —
  samma prestanda är att förvänta, men bevisas formellt först vid
  sudofönstret (appendix A).
- **Medlemsdata logiskt ur backup:** **ca 12,5 sekunder** (bevisat idag) till
  en validerad, kontrollsummerad medlemsmängd; själva filtreringen efter
  uppackning tar **1 millisekund**.
- **Att ta en färsk komplett backup:** **ca 50 sekunder** (bevisat idag).
- **Händelseloggen:** måste återinläsas via REST från moln-backupen (kap 4c);
  dumpen på 338 MB oväxlat är bevisat läsbar på ~12 s — praktisk återinläsning
  beror på nätleverantör men är mekaniskt enkel (sidindelad POST).
- **Hela plattformen (server borta):** enligt DRIFTSBOKEN kap 4b — ny VPS +
  setup-prod + kod + env + build + DNS-flipp: minuter till låga timmar;
  dokumenterad plan, ej ombevisad i detta prov.

**Sammanfattande RTO-bedömning:** data-skiktet är återställbart på
**sekundnivå** (bevisat 20 s; medlemsdata logiskt 12,5 s), komplett färsk
backup tas på **under en minut**. Den långsamma delen vid en total katastrof
är maskin- och DNS-arbetet (kap 4b), inte data. Villkoret: **båda
backupkedjorna måste finnas** (natt-SQL + moln-JSON) — se fynd §6.

## Appendix A — Exakta kommandon för nytt fullt PG-prov (VID KUNDS SUDOFÖNSTER)

Kör som användare `ak1a` på Contabo-servern (kräver sudo, därför kundfönster).
Förväntat resultat baserat på våg 98 F3: ca 20 s; 768 GRANT/ALTER-"fel" är
kända och ofarliga (saknade Supabase-roller/extensions i vanilla-PG).

```bash
# 0) Förutsättning: dagens natt-dump finns (OBS: SQL-dumpen — inte JSON-dumpen):
ls -la /home/ak1a/AK1/data/backups/supabase/db-$(date +%F).sql.gz

# 1) Starta PG17 (lämnad installerad+stoppad sedan våg 98 F3)
sudo pg_ctlcluster 17 main start

# 2) Skrap-databas (idempotent)
sudo -u postgres dropdb --if-exists ak1a_dr_test
sudo -u postgres createdb ak1a_dr_test

# 3) Mät återställningen (detta är RTO-provet)
time (zcat /home/ak1a/AK1/data/backups/supabase/db-$(date +%F).sql.gz \
  | sudo -u postgres psql -d ak1a_dr_test -q 2>/tmp/dr-restore-fel.log)

# 4) Verifiering (jämför med tabellen i §4c ovan)
sudo -u postgres psql -d ak1a_dr_test -c \
  "SELECT count(*) AS publika_tabeller FROM information_schema.tables WHERE table_schema='public';"
sudo -u postgres psql -d ak1a_dr_test -c "SELECT count(*) AS medlemmar FROM auth.users;"      # förväntat: 3
sudo -u postgres psql -d ak1a_dr_test -c "SELECT count(*) AS profiler FROM public.profiles;"  # förväntat: 3
sudo -u postgres psql -d ak1a_dr_test -c "SELECT count(*) AS snapshots FROM public.section_data_snapshots;"

# 5) Utred system_events-fyndet (§6) — vilket objekt har kolumnen 'type'?
sudo -u postgres psql -d ak1a_dr_test -c \
  "SELECT table_schema, table_name, table_type FROM information_schema.tables WHERE table_name LIKE '%system_events%';"
sudo -u postgres psql -d ak1a_dr_test -c \
  "SELECT schemaname, viewname FROM pg_views WHERE definition ILIKE '%system_events%';"

# 6) Städning (skrap-DB bort + PG17 stoppad igen)
sudo -u postgres dropdb ak1a_dr_test
sudo pg_ctlcluster 17 main stop
```

Efter provet: dokumentera tid + tabell-/radantal i DRIFTSBOKEN (huvudagenten).
